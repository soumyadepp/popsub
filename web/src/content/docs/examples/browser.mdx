## Before you start

Do the [one-time setup](/examples/#set-up-once). The page logs in as its own account,
`reader`, which may only **read** `news/`. Then let `alice`, standing in for your backend,
publish there:

```bash
POPSUB_PASSWORD=password POPSUB_NEW_PASSWORD=reader-password \
  popsub users add reader --role readonly --topic 'news/#'
popsub users grant alice 'news/#'
```

## The page

One HTML file. The client library loads from a CDN, so there's nothing to install or build.

<Code code={newsroomPage.trimEnd()} lang="html" title="index.html" />

- **Last 10** fills the page with recent headlines straight away.
- **Each headline is placed by its publish time.** History arrives topic by topic, so sorting
  keeps the newest on top.
- **The status pill** follows the connection. If the network drops, the library reconnects
  and carries on from the last headline it showed.
- **`textContent`** puts headlines on the page as text, so a headline can't inject HTML.

## Run it

Serve the page from its folder, so the browser allows the module import:

```bash
python3 -m http.server 8000
```

Open [http://localhost:8000](http://localhost:8000). Then publish a headline, and watch it
appear at the top:

## Before you ship it

The password is in the page, so anyone who opens it can read it. That's acceptable here only
because `reader` can do nothing but read public headlines. For anything private:

- Have your backend log in for the user and hand the page a **token** instead of a password.
  Pass it as `credentials: { token }`.
- Serve PopSub over **`wss://`** with TLS. See [Deploy to a server](/run/deployment/).
- Give each user an account limited to their own topics, as in
  [A private inbox per user](/examples/private-inboxes/).
