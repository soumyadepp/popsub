## Where PopSub loses

- **Large messages.** At 16 KiB, PopSub is behind all three. It writes each message to the operating system before delivering it, so a server crash never loses a message a subscriber saw, and at that size the disk can't keep up.
- **Raw speed against NATS core** on a single topic: 1.9 against 3.4 million a second. NATS core keeps nothing.
- **Latency.** A median of 0.23 ms at 1,000 messages a second, against 0.10 to 0.14 ms for the others.
- **A quiet topic beside very busy ones.** Its median rises to about 0.8 ms when the machine is nearly saturated. NATS stays under 0.1 ms.
- **Memory against Mosquitto,** which is tiny.

## How it was measured

- Apple M4 Pro laptop, macOS, 2026-11-27. The load generator ran on the same machine.
- Each broker speaks its own protocol, with no client library in between.
- 2 seconds of warm-up, then 8 seconds measured, with a quiet disk before each test.
- Not measured yet: Linux, a real network, TLS, or runs longer than a few seconds.

The [full results](https://github.com/soumyadepp/popsub/blob/main/docs/BENCHMARKS.md) have every
scenario, latency percentiles, the settings that differ from defaults, and the known limits.

## Run it yourself

```bash
make bench
make bench BENCH="--target nats-jetstream"
```

You need `nats-server` or `mosquitto` installed to compare against them.
