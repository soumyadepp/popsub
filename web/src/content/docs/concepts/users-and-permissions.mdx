<p class="lede">Every connection logs in as an account, and an account can only use the topics it has been granted.</p>

Every connection logs in as an account, and every account starts with access to nothing.

You open up topics by granting patterns, the same `+` and `#` patterns used for
[wildcard subscriptions](/concepts/wildcards-and-groups/).

## A worked example

Create `alice`, who handles orders and may read the news:

```bash
export POPSUB_PASSWORD=password
POPSUB_NEW_PASSWORD=alice-password \
  popsub users add alice --topic 'orders/#' --topic 'news/+:subscribe'
```

```text
Name:    alice
Role:    user
Enabled: yes
Topics:  orders/#:both, news/+:subscribe
```

A grant without an access level means `both`. Here's what alice can now do:

| Alice tries to | Result |
|---|---|
| publish to `orders/42` | allowed, by `orders/#` |
| subscribe to `orders/eu/7` | allowed, by `orders/#` |
| subscribe to `news/today` | allowed, by `news/+` |
| publish to `news/today` | `not_authorized`, she may only subscribe there |
| subscribe to `news/eu/today` | `not_authorized`, `+` is exactly one level |
| subscribe to `invoices/#` | accepted, but empty: she can't read any of them |

`popsub users` talks to a running server:

- It connects as `admin` on `ws://127.0.0.1:8080` unless you pass `--username` or `--url`.
- Passwords come from `POPSUB_PASSWORD` and `POPSUB_NEW_PASSWORD`, or from a prompt that
  doesn't echo, never from the command line.

## Roles

| Role | What it can do |
|---|---|
| `user` | Most accounts. Gets exactly what its grants say. |
| `readonly` | Can only ever subscribe, whatever you grant it. |
| `admin` | Can use every topic and manage accounts. Grants don't apply to it. |

## Managing accounts

```bash
popsub users list
popsub users grant alice audit --access publish
popsub users revoke alice 'news/+'
popsub users role bob readonly --topic 'metrics/#'
popsub users passwd alice
popsub users disable alice
popsub users delete alice
```

- `role` replaces an account's role and all its grants at once.
- `grant` adds one, replacing any grant for exactly the same pattern.
- The last enabled admin can't be disabled, deleted or demoted, so you can't lock yourself out.

### Changes apply immediately

Changes apply to open connections right away:

| Change | What happens to alice's connections |
|---|---|
| Revoke a topic | Her subscription to it ends right away, with an `unsubscribed` frame |
| Change her password | Closed with code 4004, so she has to log in again |
| Disable or delete her | Closed with 4009, and the client libraries don't try to reconnect |

Every client library has the same requests on `client.admin()`, if you'd rather manage accounts
from code.

## Letting people sign up

By default nobody can create their own account. Set `server.allow_registration = true` to accept
the `register` request.

New accounts get no topics unless you also set `server.registration_role`:

| `server.registration_role` | New accounts can |
|---|---|
| `readonly` | Subscribe to everything |
| `full` | Publish and subscribe to everything |

Registration is rate limited. A taken username gets the same generic error as any other
refusal, so it can't be used to find out who has an account.

## Tokens

Logging in returns a token that's valid for 24 hours (`server.jwt_expiration_hours`).

A minute before it runs out, the server warns the connection with `auth_expiring`. The client
can then log in again and send the new token on the same connection.

The client libraries do this for you when they have a password. If you gave them only a token,
the connection closes when it expires.

## Rate limits

Out of the box:

| Limit | Default |
|---|---|
| Wrong passwords for one username from one address | 5, then that pair is locked out for 5 minutes |
| Wrong passwords from one address, across any usernames | 20, then the address is locked out for 15 minutes |
| Repeat lockouts | Double, up to an hour |
| Publishing, per account | 100 messages a second, in bursts of up to 50, shared across all its connections |
| Registering, per address | 5 tries an hour |

Going over gets `locked_out` or `rate_limited`, with a `retry_after` in seconds, and the
connection stays open.

Locking out the username and address together means someone guessing alice's password from one
machine doesn't stop alice logging in from hers.

Limits are keyed on the client's address. Behind a reverse proxy, every client looks like the
proxy unless you list it in `server.trusted_proxies`.
